# Аудит и исправления Crypto Liquidity Engine

Дата: 29 октября 2026. Проект: `~/Documents/crypto-engine`.
Основание: переданное ТЗ, исходный код, автоматизированные проверки и публичные
данные Binance. Это отчёт об исправлении существующей основы, не приёмка полного ТЗ.

## Результат

До изменений 86 тестов проходили, но они не импортировали приложение целиком.
Фактический запуск блокировали неверный импорт Position и обязательный импорт
неустановленного asyncpg из выключенного Live-модуля. После изменений 108 тестов
проходят, включая импорт FastAPI и очистку ресурсов при ошибке запуска.

Исправлено:

1. Backend запускается без PostgreSQL и без подключения незавершённого Live manager.
2. `execution.enabled=true` больше не обходит запрет Live через research-режим.
3. Ошибка startup вызывает shutdown; остановка до полного старта допустима.
4. Ошибка depth reader пробуждает потребителя. Сервис повторяет синхронизацию;
   переполнение буфера немедленно инвалидирует стакан. Дельта на границе gap
   сохраняется для повторного выравнивания. INVALID/пустой стакан не считается готовым.
5. Нормальное закрытие WebSocket также включает backoff. Длинные отключения не
   вызывают числовое переполнение при вычислении задержки.
6. Health проверяет соединение, состояние стаканов и потерю данных. Гибель
   фоновых задач больше не выглядит как полностью работающий сервис.
7. Потребитель UI подписывается на свой символ; поток других пар не вытесняет
   его обновления. Частота ограничена `api.ui_update_hz`. Поздние события старого
   сокета после смены пары игнорируются.
8. Ограничены буфер подсказок сделок и журнал последних переходов стен.
9. Parquet shutdown не отменяет активный поток записи. Ошибка диска отражается
   в потерях. Имена файлов включают ID сессии; завершённый файл публикуется
   атомарно. Запись группируется до 50 мс вместо мелких row groups на каждый тик.
10. Читатель не выбрасывает последний завершённый файл. Replay использует
    управляемое время, прогрев до start, ограничение end и порядок ingestion.
11. Заменён неработавший скрипт backtest: один стакан, последующие события,
    комиссия, задержка, объём впереди в очереди, частичные fills и spot-инвентарь.
    Все допущения выводятся в отчёте. Это базовая исследовательская модель.
12. Исправлены единицы account commission: значение 10 означает 10 bps,
    а не 1000 bps. Комиссии аккаунта не означают полный учёт скидок/налогов.
13. Docker устанавливает dev-зависимости для сборки frontend, включает README
    для Python packaging и использует Python healthcheck вместо отсутствующего curl.
    Добавлен .dockerignore; node_modules не копируются в runtime.
14. Исправлена зависимость `httpx2` → `httpx`; asyncpg вынесен в optional extra.
15. Документация больше не утверждает готовность отсутствующих возможностей.

## Проверки

В рабочей копии с Python 3.13 и установленными зависимостями исходного проекта:

- `python -m pytest`: **108 passed**.
- `ruff check backend scripts`: **All checks passed**.
- `mypy backend/app`: **Success**, 57 исходных файлов.
- `npm run build`: TypeScript и Vite успешно, 40 модулей.
- Реальное публичное подключение BTCUSDT: за 1.8 с получены READY, 399 уровней,
  2 публичные сделки, gaps=0, resyncs=1, dropped_diffs=0. Реальные ордера не отправлялись.
- Выборка 2 000 событий из `raw_events-20261029T161707-00001.parquet`:
  replay READY, 399 уровней, 330 снимков признаков, 120 переходов стен, gaps=0.
- Бэктест той же выборки: 0 сделок, 0 позиции, неизменный виртуальный баланс.
  Это не подтверждает прибыльность.
- Полный архив: прогон остановлен из-за длительного времени чтения/обработки;
  не засчитан как успешная проверка.
- Docker недоступен; контейнер и PostgreSQL не запускались.

Публичный протокол сверялся с официальными источниками:
- https://github.com/binance/binance-spot-api-docs/blob/master/web-socket-streams.md
- https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md

## План по фазам и фактическая готовность

| Фаза ТЗ | Сейчас | Осталось для приёмки |
|---|---|---|
| 1 Infrastructure | Локальный backend/UI и проверки работают | Проверка Docker, PostgreSQL, миграции, воспроизводимая чистая установка |
| 2 Market Data | Публичные данные, стакан, trades, scanner, recorder; короткая онлайн-проверка пройдена | Полный raw stream, session/sequence/gap markers, границы покрытия L2, длительный тест 10–30 пар |
| 3 Analytics | Spread, OBI, OFI, microprice, CVD и стены | Расчёт на каждом событии, корректная привязка агрессивных сделок к стенам, проверка absorption |
| 4 Strategy Research | Одна базовая стратегия/отдельные заготовки | Три независимые стратегии, сохранение решений, forward outcomes, исследовательский отчёт |
| 5 Backtesting | Рабочий консервативный CLI baseline | Исторические filters, cancel latency, exit/slippage, walk-forward, holdout, масштабируемый replay |
| 6 Paper Trading | Не принят; отдельные модули не составляют рабочий цикл | Virtual account, резервы, Order/Position/Exit Engine, risk gates, восстановление, UI |
| 7 Live Trading | Заблокирован | Auth, private stream по актуальному API, UNKNOWN, idempotent fills, reconciliation, guards, аварийные сценарии |
| 8 Optimization | Не начат | Только после воспроизводимой проверки фаз 4–6 |

Следующий технический приоритет — закончить phase 2 и измерение сигналов phase 3,
после этого строить Paper Trading на проверенном event-driven ядре. Снимать запрет
Live до отдельной приёмки нельзя. Полный перечень ограничений — LIMITATIONS.md.
