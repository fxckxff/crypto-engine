# Торговая система: Paper Trading

Реализовано 29 октября 2026 года. Это виртуальное spot-исполнение на публичных
данных Binance, а не Live Trading. Реальные ордера по-прежнему заблокированы.

## Запуск

```sh
cd ~/Documents/crypto-engine
make paper
```

Откройте http://127.0.0.1:8000 и блок «Торговая система PAPER».
Нажмите «Запустить Paper». Новый счёт содержит 1 000 виртуальных USDT.
После любого перезапуска счёт восстанавливается на паузе.
`make run` по-прежнему запускает исследовательский профиль.

## Что работает

- Виртуальный счёт USDT, свободный/зарезервированный баланс, себестоимость,
  средняя цена, комиссии, реализованный и нереализованный PnL.
- POST_ONLY и IOC LIMIT; задержка подачи и отмены, TTL, частичные исполнения.
- Консервативная очередь: объём впереди на момент подтверждения заявки,
  последующие встречные агрессивные сделки точно на цене лимита.
  Снятие заявок впереди не ускоряет очередь.
- IOC проходит по доступным уровням в пределах цены; уже использованный объём
  одного update ID повторно не используется. Остаток IOC истекает.
- Идемпотентный client_order_id, отказ при повторе ID с другими параметрами,
  дедупликация публичных trade ID, сохранение watermark.
- Запрет short без актива, усреднения, заявок без свежего стакана и нарушение
  tick/step/min quantity/max quantity/min notional.
- Проверки риска общие для автоматических и ручных заявок: баланс с комиссией,
  экспозиция и число позиций с учётом ожидающих BUY, лимит заявок в минуту,
  дневной убыток/просадка, общая просадка, серия убыточных закрытий, широкий спред.
- Выходы: пассивный take profit, STOP_LOSS, TIME_EXIT, WEAKNESS_EXIT,
  WALL_FAILURE, EMERGENCY_EXIT. Причина сохраняется в журнале.
- «Стоп + отмена заявок» сохраняет активы. «Закрыть позиции в пределах лимита»
  пытается продать через ограниченный IOC; отсутствие ликвидности, устаревшие
  данные и биржевые минимумы не скрываются. Dust остаётся видимым.
- Стратегии «Сбор спреда», «Ликвидность стен» и «Микроструктура» с независимыми
  параметрами. Вход по стене требует времени жизни, поглощения и OBI/OFI.
  Микроструктурный вход требует согласованности OBI/OFI/microprice/потока.
- Настройка трёх стратегий, ручные виртуальные заявки, таблицы позиций/ордеров,
  журнал исполнений и причины ожидания в браузере.

## Настройки

`configs/paper.yaml`: режим paper и обязательный `risk.enabled=true`.
Параметры счёта задаются секцией `paper` (значения по умолчанию в
`backend/app/paper/config.py`). Глобальные лимиты — секция `risk`.

По умолчанию активна только стратегия сбора спреда. Другие включаются в UI.
На BTCUSDT и ETHUSDT узкий спред обычно не покрывает заданные комиссии и резерв
издержек, поэтому отсутствие сделок ожидаемо. Не следует снижать пороги только
ради появления сделок. Причина отказа показана для каждой пары и стратегии.

`market_data.max_data_age_ms=500` — строгий порог свежести. Даже краткий период
без depth-обновлений может остановить Paper. После устранения причины нужен
явный повторный запуск. При реальной потере данных требуется проверка и
перезапуск сервиса: счётчик потерь намеренно не сбрасывается кнопкой.

Настройки Paper и стратегий сохраняются вместе со счётом; после восстановления
используются сохранённые значения. Изменения стратегий через UI сохраняются
сразу. `initial_cash` задаёт только новый счёт, а не сбрасывает существующий.
Для независимого эксперимента укажите новый `paper.database_path`; удалять
существующий счёт не нужно.

## Хранение и восстановление

Локальная база: `datasets/paper/account.sqlite3`, SQLite WAL, synchronous FULL.
Снимок счёта и события записываются одной транзакцией в фоновом потоке, команды
сериализованы asyncio-lock. Checksum проверяется при чтении. Два процесса не
могут открыть один счёт на запись (локальная file lock, macOS/Linux).

При ошибке сохранения изменения откатываются в памяти, исполнение блокируется.
После перезапуска восстанавливаются cash, позиции, комиссии, PnL, лимиты,
конфигурация стратегий и история ордеров. Непогашенные виртуальные заявки
отменяются: очередь во время отсутствия процесса неизвестна. Автовозобновления нет.
Реальная биржевая reconciliation этим не заменяется.

SQLite выбран для полностью локального Paper без внешнего сервера. Это
осознанное отклонение от PostgreSQL-стека полного ТЗ. PostgreSQL и multi-worker
торговый runtime остаются отдельным этапом; старый Live manager не используется.

## Один движок для Paper и backtest

`backend/scripts/paper_backtest.py` использует тот же `PaperEngine`: стратегии,
риски, очереди, комиссии, исполнение, позиции и выходы не дублируются.
Исторические торговые фильтры задаются явно; текущие правила биржи не
выдаются за исторически подтверждённые.

```sh
PYTHONPATH=backend .venv/bin/python -m scripts.paper_backtest \
  --dataset datasets/raw --symbol BTCUSDT \
  --tick-size 0.01 --step-size 0.00001 --min-quantity 0.00001 \
  --max-quantity 9000 --min-notional 5
```

Числа в примере — входные допущения, требующие проверки для исторического
периода. Старый `scripts/backtest.py` оставлен как предыдущий исследовательский
baseline; для сопоставления с новой торговой системой используйте paper_backtest.

## API

Чтение: `GET /api/paper/status`, `/api/orders`, `/api/positions`, `/api/trades`,
`/api/paper/events`, `/api/strategies`, `/api/strategies/{name}`.

Команды: `POST /api/paper/start`, `/api/paper/stop`, `/api/paper/flatten`,
`/api/paper/orders`, `/api/paper/orders/{id}/cancel` и
`PUT /api/strategies/{name}/config`.
Изменяющие запросы требуют `X-Paper-Command: 1`; Origin проверяется.
Это защита локального браузерного интерфейса, не полноценная удалённая авторизация.
Сервис остаётся на 127.0.0.1.

## Проверки

- 140 тестов проходят; Ruff и mypy проходят (64 модуля); TypeScript/Vite собираются.
- Проверены: комиссии, резервирование, запрет short, round-trip PnL, очередь,
  частичные fills, дубликаты, fill во время отмены, отказ post-only после задержки,
  stale book, дневной лимит, time exit, partial IOC, dust, восстановление счёта,
  ошибка диска, один писатель, API/Origin, неизменность research-режима.
- Браузер: интерфейс отображается, запуск Paper работает, JS errors не обнаружены.
- Отдельный реальный публичный поток: виртуальная покупка 0.00024 BTC,
  перезапуск с позицией, восстановление на паузе и контролируемое закрытие.
  Итог тестового счёта 999.9818540776 USDT; комиссии 0.0387835224 USDT;
  реализованный PnL −0.0181459224 USDT; открытых позиций нет.
  Тестовые сделки не перенесены в основной счёт.
- Replay 2 000 сохранённых событий через PaperEngine: без gaps, 0 fills
  при исходных ограничениях. Синтетический повторный прогон детерминирован.

## Ограничения и следующие этапы

Это работающий Paper-контур, но не приёмка всех фаз полного ТЗ.

- Сигналы и net-edge — эвристические фильтры с измеренными признаками и
  заданным резервом издержек; модель ожидаемой доходности не откалибрована.
  Нет независимого holdout, walk-forward и статистического доказательства прибыли.
- L2 не раскрывает реальную очередь/hidden liquidity. Комиссии моделируются
  в USDT, без BNB-скидок, fee-in-base и индивидуальных налоговых ставок.
- IOC ограничен видимой глубиной; повторный update ID считается новым состоянием,
  а не доказательством обновления всей ликвидности. Точная очередь неизвестна.
- Правила инструмента — поддерживаемый набор tick/lot/notional; динамические
  percent-price и другие фильтры не полностью реализованы. Фильтры не обновляются
  в runtime. Поддерживаются только пары с котируемой валютой USDT.
- Постоянное состояние содержит историю ордеров; длительные тяжёлые сессии требуют
  нормализованного хранилища/архивации и отдельного нагрузочного теста.
- Временная модель использует локальное wall-clock для persistence; скачки NTP
  и большие задержки доставки требуют отдельной проверки. Paper запрещает fills
  на старых exchange timestamps относительно времени активации заявки.
- Полный исторический wire stream, gap/session markers, масштабируемый replay,
  PostgreSQL, единый Backtest Laboratory в UI и точные метрики задержек остаются.
- Live по-прежнему недоступен: нет принятой приватной execution/reconciliation
  инфраструктуры, UNKNOWN-ордеров и защищённого контура авторизации.
