# Актуализация после реализации Paper Trading

Рабочий Paper-контур реализован: см. [PAPER_TRADING.md](PAPER_TRADING.md).
Ниже сохранён исходный аудит предыдущего этапа. Утверждения об отсутствии
Paper Trading, трёх стратегий и торговой панели относятся к состоянию до этого
изменения; актуальные ограничения перечислены в новой инструкции.

# Известные ограничения — 2026-10-29

## Что пока нельзя считать готовым

- Полный цикл Paper Trading, три независимые стратегии, конфигурация стратегий
  через UI, история позиций/ордеров, Exit Engine и восстановление торгового
  состояния не реализованы как единая работающая система.
- Live Trading заблокирован. Незавершённый менеджер содержит упрощённый учёт
  позиций и reconciliation; он не подключается к монитору. Нельзя снимать блокировку
  до тестов приватного потока, дедупликации fills, UNKNOWN-ордеров, балансов,
  резервов, авторизации и восстановления после сбоев.
- PostgreSQL-каталог — отдельный незавершённый модуль. `storage.database` не
  включает полноценную интеграцию/миграции. В Compose PostgreSQL пока отсутствует.
- HTTP-сервис предназначен для режима research. Метки paper/backtest в схеме
  конфигурации сами по себе не реализуют соответствующий runtime; для offline
  исследований используются отдельные CLI-команды.
- Проверена одна spot-биржа — Binance. Bybit и деривативы отсутствуют.

## Рыночные данные

- REST snapshot не сообщает exchange event timestamp. Задержка доставки WS
  зависит от синхронизации часов. Гарантий задержки нет.
- L2 не раскрывает очередь отдельных заявок, скрытую ликвидность и точное
  разделение отмен/исполнений. Оценки стен не являются доказательством намерений.
- Стакан хранит ограниченное число уровней; корректность глубокой ликвидности при
  длительном движении цены требует теста границ покрытия и периодического refresh.
- OFI/стены считаются по тактам признаков; все промежуточные изменения могут не
  попасть в эти признаки. Пороги стен сейчас ориентированы на BTCUSDT.
- Историческая схема записывает применённые depth-события, а не полный исходный
  wire stream. Отброшенные/неприменённые дельты не восстановить по такой записи.
  Требуется отдельная версия схемы с session ID, порядковым номером и gap markers.
- После транспортного переподключения непрерывность проверяется через update ID;
  отдельного reconnect marker в историческом датасете пока нет.
- Торговые фильтры загружаются при старте; автоматического обновления нет.
- Testnet требует явных URL. Один флаг `testnet` не переключает endpoint.

## Запись и replay

- Запись буферизуется до 50 мс; при аварийном завершении процесса возможна потеря
  последнего буфера и незавершённого файла. `.partial` не считается завершённым.
- Запись использует zstd. Ошибки диска/очереди отражаются в `data_loss`.
- Старые файлы без footer пропускаются; их восстановление не выполнялось.
- Offline loader загружает выбранный символ в память и сортирует по ingestion.
  Большие архивы с множеством маленьких row groups медленны. Полный прогон архива
  пользователя не завершён; проверена выборка из 2 000 событий.
- Время ingestion — wall-clock; для строгого порядка при скачках часов нужен
  записанный session/sequence ID. Старые файлы его не содержат.
- Retention реализован как метод, но автоматический планировщик не подключён.

## Бэктест

- Реализована одна базовая passive spread-стратегия с FIFO-оценкой объёма впереди,
  заданными комиссиями, задержкой, сроком заявки и частичными исполнениями.
- Fill происходит только по последующей встречной агрессивной сделке ровно на
  цене заявки; отмены впереди не улучшают очередь. Короткие spot-позиции запрещены.
- Исторические биржевые filters, скрытая ликвидность, adverse selection,
  cancel latency и рыночная ликвидация не моделируются полностью.
- Остаток позиции оценивается по последнему bid; это не исполненная продажа.
- При разрыве последовательности итог помечается `incomplete_data` и доходность
  не выдаётся. Нет walk-forward, независимого holdout и статистической приёмки.
- Нулевое число сделок и нулевая доходность не подтверждают эффективность.

## Проверка окружения

- 108 автоматизированных тестов, Ruff, mypy и сборка frontend прошли.
- Короткая публичная сессия BTCUSDT: READY, получены сделки, без sequence gaps.
- Docker отсутствует в окружении; контейнер и PostgreSQL не проверены.
- Длительная нагрузка на 10–30 инструментов, заполнение реального диска,
  потеря питания и полноценный UI browser test остаются отдельными проверками.
